    The action library assigns risk levels. The model selects actions using action_id, and cannot modify their risk levels. Approval requirements are enforced by code. Low-risk actions support batch approval. Medium-risk actions require individual approval and impact acknowledgement. High-risk actions require a change-ticket number and approver.

    How scores are calculated
    
        
    
          
    
            The rule baseline selects the top pre-analysis vote and recommends repair for hardware classifications.
            This lookup-based approach misses cases requiring
            30-day trend analysis and separation of secondary events from root causes.
            The model path can use these additional signals.
            

    
            Scores come from scripts/verify_triage.mjs  and the local page calculation.
            Both use the same code.
            If the baseline produces 11/14, the page displays 11/14.

    Runtime
    
      
    
        
    
          This static site uses Firebase Hosting. Triage logic runs in the browser.
          Gemini uses Firebase AI Logic with platform-managed API keys.
          Patrol reads and writes cluster state through Cloud Firestore.
          When models are unavailable, the site falls back to the limited offline rule path.
          

    
          This application uses no production clusters. Cases are synthetic and patrol nodes are simulated.
          Production Tencent Cloud / Alibaba Cloud / Baidu Cloud / Zhixing Cloud clusters have no network connection to Google Cloud.
          The repository README describes this boundary.
