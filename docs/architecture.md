# 架构说明

## 1. 问题定义

多云 GPU 集群里最普遍的浪费不是「卡坏了」，而是**预留与使用的错配**：

| 模式 | 现象 | 现有监控能不能发现 |
|---|---|---|
| 超额预留 | 申请 8 卡，实际只跑 4 卡，另 4 卡全程占位 | 能，但没人天天看 |
| 长期空转 | 卡被占用，平均利用率 < 5% | 能，但缺上下文 |
| 低效运行 | 利用率 5%~30% 之间，长期不收敛 | 难，需要跨周期对比 |

传统监控只回答「现在利用率多少」，不回答**「这些浪费值多少钱、该先动哪个、动了能省多少」**。本项目补的就是这一步。

## 2. 数据流

```
监控平台导出（云 / 节点 / 卡型 / 预留卡数 / 使用卡数 / 时长 / 平均利用率）
        │
        ▼
┌─────────────────────────┐
│  analyzer.py  纯计算层  │  浪费卡时 → 电耗 → 电费 → 碳排，并判定浪费模式
│  无网络、无 AI 依赖     │  ← 可独立单元测试，结果可复算
└─────────────────────────┘
        │  结构化审计结果（summary + findings）
        ▼
┌─────────────────────────┐
│  ai.py  AI 诊断层       │  把数字喂给 Gemini，产出：浪费画像 / 根因推断 /
│  Gemini generateContent │  优化动作 / 需要补充的数据
│  失败自动降级为离线模板 │
└─────────────────────────┘
        │
        ▼
   Flask Web（Cloud Run）  →  指标卡 + AI 诊断 + 明细表
```

**分层原则**：所有数字由 `analyzer.py` 确定性算出，AI 只负责解释与建议。这样做的三个好处：

1. 数字可复算、可审计，不会出现「AI 编了个数」的情况；
2. 没有密钥、没有网络时系统仍然能完整演示（降级为离线模板）；
3. 评测「技术质量」时，能清楚说明哪部分是模型能力、哪部分是工程确定性。

## 3. 计算口径（全部假设显式声明）

设：`requested` 预留卡数，`used` 实际使用卡数，`H` 时长（小时），`U` 平均利用率（%）。

**浪费卡时**

```
申请未用卡时 = max(requested - used, 0) × H
低效折算卡时 = used × H × (1 - U/100)     仅当 U < 30
浪费卡时     = 申请未用卡时 + 低效折算卡时
```

**折算系数**

| 系数 | 取值 | 来源与说明 |
|---|---|---|
| 空转功率系数 | 0.25 | 业界经验值：闲置 GPU 功率约为 TDP 的 20%~30%，取中值 |
| 工业电价 | ¥0.70 / kWh | 可配置，按实际账单替换 |
| 碳排因子 | 0.581 kgCO₂e / kWh | 全国电网平均排放因子 |
| 低效阈值 | 30% | 低于此值判定为「低效运行」 |
| 空转阈值 | 5% | 低于此值判定为「长期空转」 |
| 成年树年固碳 | 18 kg | 用于把碳排换算成直观当量 |

**卡型参数**（`analyzer.py: GPU_SPECS`，可按实际台账替换）

| 卡型 | TDP (W) | 卡时单价 (¥) |
|---|---|---|
| H800 | 700 | 24.0 |
| H100 | 700 | 28.0 |
| H20 | 400 | 12.0 |
| A100 | 400 | 15.0 |
| V100 | 300 | 8.0 |

> 未识别的卡型统一走 `DEFAULT_SPEC`（400 W / ¥15），不会因脏数据让整个批次失败。

## 4. 已知限制

1. **能耗用 TDP × 空转系数近似**，不是实测功耗。要精确需要接入 DCGM / IPMI 功耗读数。
2. **利用率按周期平均**，会掩盖「前 80% 时间满载、后 20% 空转」这类分布问题。
3. **未做任务级归因**——知道哪个节点浪费，但不知道是哪个任务造成的。补任务队列与卡分配的关联数据后可升级。
4. **电价与碳排因子是常量**，未按地域/时段区分。真实账单是非线性阶梯电价，且不同区域电网碳排因子差异明显。

## 5. 升级路径

| 阶段 | 动作 |
|---|---|
| 近期 | 接入真实监控导出（Prometheus / 云 API），替换示例数据 |
| 近期 | 接 DCGM 功耗实测值，把空转系数换成实测曲线 |
| 中期 | 增加任务维度，实现逐任务归因 |
| 中期 | 迁移到 Vertex AI + Gemini，使用托管部署与 IAM 鉴权替代 API Key |
| 远期 | 从「事后审计」升级为「事前预测」：在配额审批环节预估浪费风险 |
