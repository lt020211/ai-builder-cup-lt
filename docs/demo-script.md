# 演示视频脚本（目标时长 2 分 40 秒，硬上限 3 分钟）

> 官方要求演示视频 **少于 3 分钟**。先写分镜再录屏，比录完再剪省时间。

## 录制前检查

- [ ] 服务已部署到 Cloud Run，拿到可公开访问的 URL
- [ ] `GEMINI_API_KEY` 已在 Cloud Run 配置为 Secret，页面上显示「由 gemini-2.5-flash 生成」
- [ ] 浏览器缩放调到 110%，地址栏与书签栏隐藏（`Cmd+Shift+B`）
- [ ] 关闭所有通知（勿扰模式）
- [ ] 提前点过一次「分析」，确认响应在 5 秒内

## 分镜

| 时间 | 画面 | 口播（中文，可直接念） |
|---|---|---|
| 0:00–0:15 | 停在首页 | 「我们管理多云 GPU 集群。最常见的浪费不是卡坏了，而是**预留了卡、却没在用**。传统监控能告诉你利用率是多少，但不会告诉你这些浪费值多少钱、该先动哪一个。」 |
| 0:15–0:30 | 点击「加载示例数据并分析」 | 「这就是我们要补的一步。数据来自监控平台的导出：预留卡数、实际使用卡数、时长、平均利用率。」 |
| 0:30–0:55 | 四张指标卡出现 | 「一个周期下来，浪费 X 卡时，折合电费 X 元、电耗 X 度、碳排 X 公斤——相当于 X 棵树一年的固碳量。」（**念屏幕上的真实数字，不要背稿**） |
| 0:55–1:35 | 滚到 AI 诊断区 | 「关键在这里。所有数字都是确定性计算出来的，AI 只做一件事：解释为什么。它给出了三件事——浪费集中在哪、根因是什么、按收益排序该先做哪三步。每一条都要求引用具体节点和数字作为证据。」 |
| 1:35–2:05 | 指着诊断里的一条根因 | 「比如这条：某个节点申请了 8 卡，实际只用了 4 卡，另外 4 卡占位了一整周。这是数据直接确认的结论，不是猜测。」 |
| 2:05–2:30 | 滚到明细表 | 「明细表按浪费金额排序，带严重等级，可以直接派给对应的团队去处理。注意到右侧这一列——把申请卡数下限和实测峰值对齐，就是收益最高的第一步。」 |
| 2:30–2:40 | 回到指标卡 | 「这就是 GPU 算力浪费审计器：把监控里没人看的数字，变成能直接排期的能效优化动作。」 |

## 剪辑要点

- **数字必须真实**：所有口播里的数字都要与录屏画面一致。评审会对照。
- 不要配背景音乐压过人声；旁白优先。
- 加字幕（B 站/YouTube 自动字幕不稳，中文识别会错）。
- 结尾留 2 秒静态画面，不要突然黑屏。

## 备选素材（如果时间有富余）

- 展示 `docs/architecture.md` 里的分层图，强调「确定性计算 + AI 解释」的设计取舍——这是技术分的加分点。
- 展示离线降级：删掉 API Key 后页面依然能跑，只把诊断换成规则模板。这能证明系统不是「套壳对话机器人」。
