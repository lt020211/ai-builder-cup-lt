# 演示视频脚本（目标时长 2 分 40 秒，硬上限 3 分钟）

**语言：** [🇬🇧 English](demo-script.en.md) ｜ 🇨🇳 中文

> ⚠️ **先决定口播语言再录屏。** 这是 JAPAC 区域赛，评审未必听得懂中文。
> 本文件是中文口播版；`demo-script.en.md` 是英文口播版，两版分镜完全一致。
> **建议：英文口播 + 中英双语硬字幕**——口播用评审的语言，字幕保留中文便于你自己核对数字。
> 若坚持中文口播，务必加英文硬字幕，否则语言会成为非技术性失分项。

> 官方要求演示视频 **少于 3 分钟**。先写分镜再录屏，比录完再剪省时间。
>
> **录制策略**：本项目的差异化在于「AI 自己调工具取数」和「碳感知调度」两点，
> 因此视频必须让这两点在画面上**看得见**——工具调用轨迹要入镜，碳曲线要点出来。
> 只展示「AI 写了一段话」会丢掉技术上最容易得分的地方。

## 录制前检查

- [ ] 服务已部署到 Cloud Run，拿到可公开访问的 URL
- [ ] `GEMINI_API_KEY` 已配置为 Cloud Run Secret，页面显示「由 gemini-3.8-flash 自主调用工具生成」
- [ ] **确认页面上「AI 的工具调用轨迹」有内容**（若显示「离线模式未调用工具」，说明密钥没生效，先修）
- [ ] 浏览器缩放调到 110%，地址栏与书签栏隐藏（`Cmd+Shift+B`）
- [ ] 关闭所有通知（勿扰模式）
- [ ] 提前点过一次「分析」，记录响应耗时；若超过 20 秒，考虑先录屏再剪辑等待段

## 分镜

| 时间 | 画面 | 口播（中文，可直接念） |
|---|---|---|
| 0:00–0:15 | 停在首页 | 「我们管理多云 GPU 集群。最常见的浪费不是卡坏了，而是**预留了卡、却没在用**。传统监控能告诉你利用率是多少，但不会告诉你这些浪费值多少钱、该先动哪一个。」 |
| 0:15–0:30 | 点击「加载示例数据并分析」 | 「数据来自监控平台导出：预留卡数、实际使用卡数、时长、平均利用率，以及负载的运行时段。」 |
| 0:30–0:50 | 四张指标卡出现 | 「一个周期下来，浪费 X 卡时，折合电费 X 元、电耗 X 度、碳排 X 公斤。」（**念屏幕上的真实数字，不要背稿**） |
| 0:50–1:20 | 滚到「电网碳强度时段曲线」 | 「但碳排还有一个更少被注意的维度：**什么时候跑**。这条曲线是一天 24 小时的电网碳强度——正午光伏出力高峰时碳强度最低，晚高峰火电调峰时最高，相差超过 30%。这意味着**电耗不变、电费不变，只把负载挪个时段，碳排就能降下来**。」 |
| 1:20–1:50 | 滚到「AI 的工具调用轨迹」 | 「关键设计在这里：**AI 不生成数字，它调用工具取数字**。它先调 `query_metrics` 拿明细，再调 `simulate_defer` 算挪时段的减碳量，最后用 `propose_action` 把建议登记进决策清单。屏幕上这条轨迹就是它的每一次调用——所有数字都能追溯到某次工具返回值。」 |
| 1:50–2:15 | 滚到「决策清单」，点一条「接受」 | 「所以它的产出不是一份报告，而是一张**决策清单**：空转节点自动回收、回收超额预留、把高耗节点挪到低碳时段。每条都带预计回收金额和预计减碳量。我点『接受』，收益就实时累加。」 |
| 2:15–2:30 | 指着减碳汇总数字 | 「注意最后这条：挪时段不省电费，但省碳。消除浪费和调整时段是两条独立的减碳路径，我们把它分开算了。」 |
| 2:30–2:40 | 回到指标卡 | 「这就是 GPU 算力浪费审计器：把监控里没人看的数字，变成能直接排期的能效与碳排决策。」 |

## 剪辑要点

- **数字必须真实**：所有口播里的数字都要与录屏画面一致。评审会对照。
- 工具调用轨迹那一段**不要加速跳过**，让观众看清工具名与参数。
- 不要配背景音乐压过人声；旁白优先。
- 加字幕（B 站/YouTube 自动字幕不稳，中文识别会错）。
- 结尾留 2 秒静态画面，不要突然黑屏。

## 备选素材（如果时间有富余）

- 展示 `docs/architecture.md` 里的分层图，强调「确定性计算 + AI 决策」的设计取舍——这是技术分的加分点。
- **展示离线降级**：不配 API Key 时页面依然能跑，工具轨迹显示「离线模式未调用工具」，
  但决策清单仍由规则产出。这能证明系统不是「套壳对话机器人」，而是有完整工程兜底。
- 展示 `/api/carbon-profile` 的 JSON 返回，证明碳曲线是可被外部消费的一等接口，不只是装饰性图表。

## 若时间超限的删减顺序

1. 先删 0:15–0:30 的数据来源说明（合并进前一段口播）
2. 再删 2:15–2:30 的「两条路径」说明（保留画面，口播压成半句）
3. **不删** 碳曲线段与工具轨迹段——这两段是本项目的得分点
