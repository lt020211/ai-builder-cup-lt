# 演示视频脚本 · 训练故障分诊器（值班 Agent）

**语言：** [🇬🇧 English](demo-script.en.md) ｜ 🇨🇳 中文

> ⚠️ **先决定口播语言再录屏。** 这是 JAPAC 区域赛，评审未必听得懂中文。
> 本文件是中文口播版；`demo-script.en.md` 是英文版，两版分镜**逐条对应**。

> **交付的成片已经按「英文口播文案 + 中英双语硬字幕」落地**：
> 画面上的英文字幕就是 `scripts/record_demo.mjs` 里 `BEATS[].caption`，
> 中文行是 `BEATS[].zh`。本文件的口播稿是**逐拍对应的完整叙述**，
> 比硬字幕长（字幕按 2 行上限裁过），用来配音或写讲解词。

> 官方要求演示视频 **少于 3 分钟**。本脚本按 **2:45** 排，留 15 秒余量。

## 这份成片是脚本产出的，不是剪出来的

```
node scripts/record_demo.mjs                    # 按分镜检查真的走一遍线上站点 → shots-demo/
python3 scripts/demo_voice.py                   # 逐拍合成英语旁白并贴合时间窗 → shots-demo/voice.m4a
python3 scripts/demo_caption.py --dir shots-demo \
        --out docs/Training-Failure-Triage-demo.mp4 \
        --voice shots-demo/voice.m4a            # 烧双语硬字幕 + 进度条 + 混入旁白 + 编码
```

拆成三步是为了**可重跑**：字幕、进度条、码率都放在合成那一步，改文案只要重跑合成，
不用重录（重录 = 再花一次模型配额）。字幕出现的时刻直接取录制时记下的
每一拍真实起止时间（`shots-demo/timeline.json`），不做剪辑拼接，所以画面与字幕天然对齐。

旁白也走同一条逻辑，而不是反过来：**先合成，量出真实时长，再决定语速**。
某一拍的话装不进它那一拍的时间窗，说明这句话该改短，不是该念快。
语速调整卡在 **−15% ~ +30%**（`scripts/demo_voice.py` 的 `RATE_MIN` / `RATE_MAX`），
顶到边界的拍会在日志里列出来，先看那几行再决定要不要改文案。
宽窗口的镜头（例如工具轨迹那一拍）宁可留几秒静音让人看屏幕，也不把一段话拧成快放。

> ★ **帧序列被清掉之后不要重录。** `shots-demo/frames/` 是几百 MB 的中间产物，
> 可能被清理掉；一旦没了，为了换个音轨或改句字幕就重录一遍是本末倒置 —— 更糟的是，
> 一次巡检的真实结果（调用次数、被 cordon 的节点）会变，而 deck 与文档里引用的正是那一组数字，
> 一重录全套证据链就对不上了。按要改什么选一条：
>
> **只换音轨**（画面一个像素不动）：
>
> ```
> python3 scripts/demo_caption.py --attach <已有成片.mp4> \
>         --voice shots-demo/voice.m4a --out docs/Training-Failure-Triage-demo.mp4
> ```
>
> 视频轨 `-c:v copy` 原样搬过去（逐字节一致，无代际损失）。
>
> **要改字幕**（画面仍需重编码一次）：
>
> ```
> python3 scripts/rebuild_frames_from_film.py          # 从成片里裁掉字幕条，取回未被遮挡的画面
> python3 scripts/demo_caption.py --dir shots-reburn --beats shots-demo/beats.json \
>         --voice shots-demo/voice.m4a --min-band-h 133 \
>         --out docs/Training-Failure-Triage-demo.mp4
> ```
>
> 字幕条只盖住最下面 133px，裁掉它就取回了全部屏幕内容 —— **屏幕一个像素没动，
> 换掉的只是我们自己写的那层字幕**。代价是这一代要再编码一次，所以脚本默认 CRF 16 + preset slow。
>
> `--min-band-h` 不能省：裁了多少就得长回来多少。新文案折行往往比旧的短
> （这里从 133px 掉到 103px），不抬回来的话，内容和蓝线之间会露出一条 30px 的底色边。

录制脚本还会自己拦三类问题，不合格就不出片：

| 拦住什么 | 为什么 | 阈值 |
|---|---|---|
| 字幕里还留着没回填的 `{calls}` | 调用次数必须取自画面，不能字幕自己报一个数 | 直接报错 |
| 超长冻帧（画面按住不动） | 观感上像「它在思考」，实际什么都没动 | > 4s 拒绝出片 |
| 总时长超过 180s | 超时是不符合提交要求，不是「差一点」 | > 180s 拒绝出片 |
| 摊平后时长与真实时长对不上 | 变帧率摊成固定帧率时**逐帧取整**，误差同向累积 —— 视频轨会比旁白短 2 秒，`-shortest` 把最后一句旁白整段切掉，而且不报错 | 差 > 1s 拒绝出片 |
| 开录前面板不对 | 曾经整场录成「单次分诊」页而日志毫无异常 | 直接报错 |

> ★ 按下录制键之前，脚本会打印「镜头对着：tab-patrol　当前标签：值班 Agent」。
> **这一行必须亲眼看一遍** —— 面板错了，后面所有的拍摄对象都是错的。

## 这一版视频要证明的一件事

只有一件事：**它把一整段值班流程跑完了，而且「跑完」是真的。**

对照去年的总冠军 SalesShortcut（寻找客户 → 研究需求 → 生成方案 → 销售触达），
我们的四步是：**主动发现 → 主动取证 → 分诊出方案 → 自动处置 + 推进触达 + 回验**。

可以把它理解成一个「4 步都要落地」的演示：

| 环节 | 要让人看见什么 |
|---|---|
| ① 主动发现 | 没有人贴日志。点一下，Agent 自己去集群里看 |
| ② 主动取证 | 工具调用轨迹：它调了什么、参数是什么 |
| ③ 分诊出方案 | 同一个错误码，两个节点给出**相反结论** |
| ④ 自动处置 + 触达 + 回验 | 操作日志里的「回验通过」；工单草稿；通知队列 |
| ⑤ 为什么需要模型 | 规则基线 11/14，错的三题各对应一条诊断原则 |

**三个必须入镜的画面**（不然技术分全丢）：
1. **工具调用轨迹**（不是「AI 写了一段话」）
2. **操作日志里的「回验通过」**（证明执行是真的，不是界面动画）
3. **基准对照页的 11 / 14**（可复现的对照）

## 录制前检查

**先做完这一节再按录制键。** 现场出问题的成本远高于准备的成本。

### 环境
- [ ] 页面已部署到 Firebase Hosting，拿到可公开访问的 URL
- [ ] 本地能跑 headless Chrome（脚本自己用 `--headless=new` 起一个，不需要手动开浏览器）
- [ ] 不需要缩放浏览器、不需要隐藏书签栏、不需要勿扰模式 —— 画面尺寸由脚本锁定 **1600×900**

### 状态（**脚本会自己做完，并在每步失败时直接报错**）
- [ ] 点「**重置模拟集群**」→ 等操作日志真的清空
      （注意：不能数 `#events li`，零事件时那里有一条占位 li；要数带 `ok/fail/info` class 的真实事件）
- [ ] 切到「值班 Agent」标签 → 等节点卡片渲染出来
      （注意：必须点 `#tabs` 里的 `button[data-tab="patrol"]`；`#tab-patrol` 是面板 div，点它什么都不会发生）
- [ ] 集群状态显示 **「6 个节点，其中 4 个存在异常现象」**（不是 4 就说明种子数据被改过，点重置）
- [ ] 打印「镜头对着：tab-patrol」——**这一行要亲眼确认**

> 上面这些「注意」都不是理论：它们全是实际踩过的坑，每一个都让某一版录制**表面上跑得很好**
> 但内容是错的。所以现在它们都变成了脚本里的硬断言，而不是清单上的一条勾。

### 配额（★ 这一节必须认真看，现场翻车多半翻在这里）
- [ ] 值班巡检**没有缓存**（它每次都要真的跑）。所以录之前先**空跑一次巡检**，确认配额够用
- [ ] **一次巡检约消耗 12–16 次模型请求**（按轮次折算：一轮工具调用一次请求；模型偶尔并行出调用会少一些。
      撞上轮次上限触发续跑会再追加一批，见 `ai.js` 的 `MAX_RESUMES`）
- [ ] 免费层按**每个模型每天**独立计额度，实测约 **20 次/模型/天**
  → 换算下来：**一天大约够跑 5–6 次巡检**。如果当天已经调试过几轮，录之前先确认剩余额度
- [ ] 这一版成片**只录值班巡检**：单次分诊页不在分镜里，不需要预热它的缓存
      （它的缓存只在手动演示那一页时有用，见 README 的配额一节）
- [ ] 基准对照页点的是「跑规则基线」——**本地计算，零请求**
- [ ] 如果空跑时看到「由 gemini-… 直接作答，本次未调用工具」或降级提示，说明额度或上游有问题，**不要开始录**
- [ ] 记一次完整巡检的耗时：顺利时 **15–40 秒**；撞上上游 500 触发续跑时可能到 **90–120 秒**
  （续跑会自动保住已完成的动作，不会白跑，但会变慢 —— 页面会显示「上游失败过一次，已带进度续跑」）
- [ ] ★ 巡检跑得越慢，成片里留给后面几拍的余量越少。脚本会在巡检结束后打印
      「预计成片 Ns」——**这个数超过 178 就重录一次**（不是靠手速补救）

## 剪辑要点

- **数字必须真实。** 所有口播里的数字都要与画面一致。其中「一次巡检消耗多少次工具调用」
  已经由脚本从画面上读取后回填字幕（`{calls}` 占位符），所以它不可能和画面对不上。
  其余数字（53 次 / ECC 118 / 11 of 14 / 2 次 cordon）录制前对着页面核一遍，**不要背稿**。
- **工具调用轨迹**那一段不要加速跳过。
- **「回验通过」四个字必须能看清**——必要时那一帧定格 0.5 秒。
- 打开 Firestore REST 原始响应那一下**保留**。这是「执行是真的」唯一的证明方式。
- 不配背景音乐压过人声；旁白优先。
- 字幕已经烧成**中英双语**：英文字幕给评审，中文行给你自己核对数字。
- 旁白是一整条音轨（`shots-demo/voice.m4a`），由 `scripts/demo_voice.py` 逐拍合成后按真实
  时间戳拼起来，长度与视频严格相等。要换音色只改 `--voice <edge-tts 音色名>` 重跑，
  字幕与画面都不用动。要换成真人配音，用同一条接口即可：
  `python3 scripts/demo_caption.py --attach docs/Training-Failure-Triage-demo.mp4 --voice <人声.m4a> --out 成片.mp4`
- 结尾留 2 秒静态画面。

## 备选素材（时间有富余才加）

- **工具集按模式裁剪**：单次分诊拿不到 `execute_action` / `draft_ticket` / `notify_operator`
  （它没有连集群）。这能说明「能力边界是设计出来的，不是提示词求来的」。
- **上游 500 的续跑**：展示一次上游失败后「保留已完成的 N 次工具调用，换模型继续」。
  这是工程韧性的加分点，但需要正好拍到，不建议为了它重录。
- **离线降级**：断网或配额耗尽时页面自动降级为规则路径，功能完整可演示。
  这能证明系统不是「套壳对话机器人」，而是有工程兜底。
